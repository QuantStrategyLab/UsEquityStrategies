# 离线状态备份、恢复与配置草稿读回

这组接口补齐人工离线状态的备份恢复与配置草稿离开计算函数后的读回。复用现有 QPK 存储，生产依赖和实际消费者保持原合同。所有输出均不授权执行、不启用配置、不解除熔断；真实账户政策、来源发行方及实际生效仍须对应证据。

## 完整状态快照

`portfolio_state_snapshot.py` 提供 `save_daily_state_snapshot` / `restore_daily_state_snapshot` 和 `save_intraday_state_snapshot` / `restore_intraday_state_snapshot`。调用方显式提供存储对象、人工账户合同、可信来源的 `binding`、独立的 `snapshot_dir` 与 `offline_root`；恢复额外要求外部保存的 `expected_sha256`。

- 快照冻结准确身份、账户/作用域/币种、预期头部和完整链，使用 `LocalObjectStore.create_text` 独占创建、按内容摘要寻址，并完整读回。JSON 重复键、非有限数值、不完整历史和摘要不一致均拒绝。
- 原按日链完整复制；盘中链连同所有迁移祖先一起复制并核验。OPEN、原触发点、高水位、持仓保护和日初基准保持原值，不从当前余额重新初始化。
- 保存前再次核对源 checkpoint；这是一份指定头部的历史副本，不是源写者的锁。写者之后仍可前进，`source_retired=null` 不能解释成写者已停或仍获准运行。
- 恢复先在内存验证完整内容、来源连续性与当前调用方的 checkpoint，再向整个空目标目录写入。新的可信头部与旧备份不符时拒绝，不能用备份自己的摘要授予回退权限。备份和 checkpoint 同时被回退的问题仍需外部可信渠道解决。
- 恢复不覆盖、不删除、不修复原存储或已有目标。中断后已有部分记录的目标保留用于诊断，下一次恢复须另用空目录。写入结果不明时只读核对精确前缀，不盲目重发同一条记录。

快照目录与状态目录不能互相包含，必须处于明确批准的离线根目录下；拒绝 URI、路径越界与符号链接。复用现有 create-only provider，不新增云备份器或可变 latest 文件。调用方仍须控制目录，不能据此宣称防住恶意文件系统竞态。

恢复只交保留状态，`new_risk_prohibited=true`，不交配置草稿。后续仍须新鲜事件和原有资格检查。这不是断电耐久、跨机器、真实持久卷、备份保留或灾难恢复验收。

状态快照不包含配置草稿文件。恢复目录中缺少草稿时，草稿读回会保留缺口；需要原草稿与外部收据，或以新输入、新事件生成新草稿，不因恢复而重发旧配置。

## 保存草稿与只读消费者预检

`portfolio_settings_draft_io.py` 提供三个接口：

| 接口 | 具体行为 |
| --- | --- |
| `persist_portfolio_settings_draft` | 先调用原盘中预览保存接口；仅对新 EVENT、风险状态已完整读回且无缺口的合格草稿做独占创建与读回，返回外部收据和状态 checkpoint。 |
| `read_portfolio_settings_draft` | 输入原冻结 request/context/packet、当前精确 checkpoint、外部 `expected_artifact_sha256` 和独立的 `consumption_cutoff_utc`，只读核对完整草稿包。 |
| `preflight_portfolio_settings_draft` | 在相同读回检查后标记离线消费者预检通过；没有 apply 方法或生产调用。 |

草稿包覆盖完整 preview、draft、原来源时间、请求/输入摘要、政策与组合身份和确切 EVENT 头部。P4 原摘要排除了 server 确认和过期字段，外层包摘要覆盖这些字段；不能仅凭 P4 摘要认定完整内容或真实确认。

冻结计算 cutoff 保留原值。当前消费 cutoff 仅重新验证原账户、现金、费用/数量/价格、政策、观察和明示有效期；不改写来源、不新增统一 TTL。输入改变、证据过期、最新头部改变或身份迁出时要求新事件。存储文件自己的摘要不是外部可信收据，也不能证明真实发行方。

草稿写入失败不能回滚已确认的风险状态，结果分别记录 `readback_verified` 和 `artifact_readback_verified`，保留 `next_binding`。原事件重放只恢复状态，不重新生成或恢复草稿；已保存草稿的显式只读读取仍必须满足上述当前证据条件。部分文件保留，不自动删除或覆盖。

OPEN 下只可检查原减仓草稿，不能转换成买入或熔断解除权限。高级设置的确认状态保持 `REQUIRED` 时仍未确认，`confirmation_granted=false`；server 确认和 effective 字段保持空值，`application_status=NOT_APPLIED`。

## 验证边界与剩余条件

测试使用人工输入，覆盖按日/盘中完整恢复、迁移祖先、过时/未来 checkpoint、摘要/JSON 损坏、非空目录、竞争或未知写入、部分文件、智能/高级草稿、输入变化、来源过期、新 OPEN 后拒绝旧草稿及独立进程重启。研究 CI 强制执行新模块，不用依赖条件跳过替代执行证据。

仍需独立补证的项目：

1. 有效账户资金基准、风险预算、阈值/期限、三档曲线与停止/恢复政策。优化器不代填这些金融选择。
2. 真实 checkpoint、初始化、迁移和确认的可信发行方，以及完整资金流、费用和数量规则的账户适用性。
3. 旧按日写者的实际停写交接与盘中日初基准。普通 state 标记或一次无变化读回不能永久约束未改造的旧 append；本包不向旧链注入不兼容记录来制造封存。
4. 对应实际存储的持久性、权限、保留与灾备，以及实际配置消费者的版本、预检与生效读回。
5. 真实组合金融证据。没有新增真实回测、换参数/窗口或收益提升结论；B5 原决定保持。
